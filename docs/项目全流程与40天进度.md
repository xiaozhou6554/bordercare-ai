## 1. 项目目标

在没有真实跨境电商店铺、企业账号和生产数据的情况下，使用模拟商品、订单、物流、库存和政策数据，构建一个能够演示企业 AI 应用能力的本地项目。

项目最终希望跑通：

```text
用户问题
  → 接口层
  → 客服应用用例
  → Agent 识别意图和选择路径
  → RAG、订单工具、库存工具或运营查询
  → 权限和业务规则校验
  → 模型组织回答或转人工
  → 返回引用、审计日志和评测结果
```

## 2. 当前企业级架构

项目采用“模块化单体 + 清晰依赖边界”。第一阶段不提前拆微服务，但按照未来可拆分的业务模块组织设计。

```text
客户端 / 管理后台 / 定时任务
              ↓
        API 接口层
              ↓
        模块化单体应用
        ├── 客服模块
        ├── 订单模块
        ├── 商品与库存模块
        ├── 物流模块
        ├── 知识库模块
        └── 运营分析模块
              ↓
        基础设施适配器
        ├── SQLite / PostgreSQL
        ├── 向量数据库 / 搜索引擎
        ├── LLM / Embedding 网关
        ├── 缓存和对象存储
        └── 外部平台 API
```

当前代码是第一阶段可运行骨架，暂时采用全局的 `application`、`domain` 和 `infrastructure` 目录。随着模块增加，逐步迁移到按业务模块组织的结构：

```text
app/modules/
├── customer_service/       # 客服会话、Agent、人工接管
├── order/                  # 订单、支付、退款
├── catalog/                # 商品与库存
├── logistics/              # 物流与承运商
├── knowledge/              # 文档、检索和 RAG
└── analytics/             # 运营指标和只读分析
```

### 3.11 源码文件级调用、输入和输出

下面进一步说明每个源码文件内部的主要符号，以及它在当前调用链中的输入、输出和依赖。阅读代码时建议从 `app/api.py` 开始，按照调用方向向下阅读。

| 文件 | 主要类/函数 | 输入 | 输出 | 调用关系和边界 |
|---|---|---|---|---|
| `app/api.py` | `app`、`startup()`、`health()`、`chat_endpoint()` | HTTP 请求、`ChatRequest` | `HealthResponse` 或 `ChatResponse` | 被 Uvicorn 加载；调用 `initialize_database()` 和 `chat_service.chat()`；不直接访问 SQL。 |
| `app/config.py` | `PROJECT_ROOT`、`DATABASE_PATH`、`PROJECT_NAME`、`SIMULATION_MODE` | 操作系统环境变量和当前文件路径 | 项目配置常量 | 被数据库和 API 使用；以后集中放环境、日志、模型和外部服务配置。 |
| `app/schemas.py` | `ChatRequest`、`ChatResponse`、`HealthResponse` | JSON 请求体和响应字段 | Pydantic 校验对象和 OpenAPI Schema | 被 API、Agent 和测试使用；只表达接口数据，不放业务决策。 |
| `app/database.py` | `SCHEMA`、`get_connection()`、`initialize_database()`、`reset_database()` | 数据库路径、建表 SQL | SQLite 连接或初始化结果 | 被启动流程、Seed 脚本和 SQLite 仓储使用；属于底层数据库连接，不应被 Agent 直接调用。 |
| `app/chat_service.py` | `chat()` | `ChatRequest` | `ChatResponse` | 兼容门面；由 API 调用，再创建 `ChatUseCase` 和 SQLite 仓储。后续可以移除，或保留为旧接口兼容层。 |
| `app/application/chat_use_case.py` | `ChatUseCase.__init__()`、`execute()` | Repository 实现、`ChatRequest` | `ChatResponse` | 应用层用例；负责组装 Agent 和工具，不关心 SQLite 的具体 SQL。 |
| `app/application/agents/router.py` | `Intent`、`classify()` | 用户自然语言 `message` | 标准化意图枚举 | 客服 Agent 调用；当前是规则分类，后续可替换为模型分类器，但不能让模型返回任意未定义意图。 |
| `app/application/agents/customer_agent.py` | `CustomerAgent.handle()`、`_handle_order()` | `ChatRequest`、`OrderTool` | 订单、物流、政策、退款或其他问题的 `ChatResponse` | 应用层流程编排；调用 Router 和 OrderTool；不能直接执行数据库操作。 |
| `app/application/tools/order_tool.py` | `OrderTool.extract_order_id()`、`query()` | 用户消息、用户 ID、是否只查物流 | 结构化工具结果：成功、缺参数、找不到、越权或订单数据 | Agent 的白名单工具；调用 Repository 和 `OrderAccessPolicy`；这里是工具边界，不是数据库层。 |
| `app/domain/entities.py` | `Order`、`Shipment` | 数据库查询结果转换后的字段 | 不可变业务对象 | 被 Repository、工具和 Agent 使用；不依赖 FastAPI、SQLite 或模型 SDK。 |
| `app/domain/repositories.py` | `OrderRepository` Protocol | 订单号、用户 ID、审计信息 | `Order`、`Shipment` 或空值 | 定义业务层需要的能力；只定义接口，不实现 SQL。 |
| `app/domain/services.py` | `OrderAccessPolicy.can_view()` | `Order`、当前用户 ID | `True` 或 `False` | 订单访问规则；必须由代码执行，不能交给 LLM 判断。 |
| `app/infrastructure/persistence/sqlite_order_repository.py` | `find_order()`、`find_shipment()`、`record_audit()` | 订单号、用户 ID、审计动作 | 业务实体或数据库写入结果 | Repository 的 SQLite 实现；把 SQLite 行转换为业务实体，并保存审计日志。未来可替换为 PostgreSQL Adapter。 |
| `scripts/seed_db.py` | `seed()` | 无，使用固定模拟数据 | 重建并填充 `database/bordercare.db` | 开发和演示前执行；调用 `reset_database()`、`get_connection()`；不属于线上请求链路。 |
| `tests/test_api.py` | `test_health()`、`test_missing_order_id()`、`test_order_access_control()` | TestClient 请求 | 断言测试结果 | 验证 API、输入校验和越权控制；后续需要拆出领域规则、应用用例和基础设施测试。 |

## 4. 当前数据库模型和数据流

### 4.1 当前数据表

```text
users             用户身份、市场和语言
products          商品和 SKU
orders            订单主表
order_items       订单商品明细
inventory         库存数量和预警阈值
shipments         物流承运商、状态和最新事件
audit_logs        工具调用、越权和审计记录
```

当前还没有独立实现，但后续需要增加：

```text
payments          支付状态和幂等键
refunds           退款申请和审核状态
customer_sessions 会话历史和用户上下文
knowledge_docs    知识文档元数据和版本
evaluation_cases  评测问题、标准答案和结果
```

### 4.2 启动数据流

```text
执行 python scripts/seed_db.py
```

### 4.5 `/chat` 订单物流查询数据流

以用户 `U1001` 查询订单 `BC10001` 为例：

```text
POST /chat
{
  "user_id": "U1001",
  "message": "我的订单 BC10001 到哪里了？"
}
    ↓
ChatRequest 参数校验
    ↓
chat_service.chat()
    ↓
ChatUseCase.execute()
    ↓
CustomerAgent.handle()
    ↓
router.classify() → 物流查询
    ↓
OrderTool.query()
    ↓
提取订单号 BC10001
    ↓
SqliteOrderRepository.find_order()
    ↓
OrderAccessPolicy.can_view()
    ↓
确认 BC10001 属于 U1001
    ↓
SqliteOrderRepository.find_shipment()
    ↓
记录 audit_logs
    ↓
CustomerAgent 组织 ChatResponse
    ↓
返回物流状态、承运商和最新事件
```

### 4.6 越权查询数据流

```text
U1002 查询 BC10001
    ↓
找到订单，但订单归属人为 U1001
    ↓
OrderAccessPolicy.can_view() 返回 False
    ↓
记录 access_denied 审计日志
    ↓
拒绝返回订单详情
```
